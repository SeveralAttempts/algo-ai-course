# Review — DIAG-001 B1, попытка 3

Дата: 2026-07-23.

## Подтверждено

- Сборка проходит без предупреждений и ошибок; 12/12 тестов solution проходят.
- Overflow исправлен корректно: `(long)max - min` вычисляет разность в `long`; test с `int.MaxValue/int.MinValue` проходит.
- Tie-break теперь использует минимальный ключ-индекс.
- Singleton теперь возвращает `(0,1)`.
- Главная модель `max(candidate) - min(candidate)` сохранена корректно.

`Math.Abs` после `max - min` не требуется, поскольку `max >= min`, но при текущем приведении к `long` он не нарушает корректность для диапазона `int`.

## Пока не закрыто

- Явная проверка null остаётся после `Any()` и фактически недостижима.
- Empty+negative limit по уточнённому контракту должен бросать исключение, но ранний возврат происходит раньше.
- Нет отдельных tests для null, empty+negative и explicit regression `[1,2,3]`.
- Полный перебор имеет `Θ(n³)` времени вместо требуемого `O(n log n)` или лучше.

## Подсказка 1 к оптимизации

Не искать сразу готовую структуру данных. Рассмотреть окно `[left..right]` и ответить:

1. Если текущее окно уже нарушает `max - min <= limit`, может ли добавление элементов справа снова сделать его допустимым при неизменном `left`?
2. Если нет, какую границу необходимо двигать?
3. Если `right` сдвигается только вправо и `left` тоже никогда не возвращается назад, сколько суммарно сдвигов границ возможно?

После ответа отдельно решается вопрос, как быстро поддерживать min/max при добавлении справа и удалении слева. Название паттерна и структура пока не раскрываются.

### Ответ пользователя на направление подсказки

Пользователь до изменения кода распознал идею двух движущихся указателей/границ. Уточнено: вход не отсортирован; это движущееся окно, а не классический двухуказательный поиск по отсортированному массиву. Следующая трудность — поддержка min/max внутри произвольного окна.
