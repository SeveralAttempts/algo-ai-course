Текущие зелёные тесты не покрывают несколько обязательных частей контракта.

## [P1] Tie-break выбирается по значению, а не по индексу

В строке 52 среди равных по длине сегментов выбирается сегмент с минимальным первым **значением**:

```csharp
dict.Select(x => (values[x.Key], x)).MinBy(y => y.Item1)
```

Контракт требует минимальный `Start`. Уже существующий тест содержит контрпример:

```text
[5,14,23,0,9,18], limit 9
```

Максимальная длина равна 2. Допустимы `[5,14]` со start 0 и `[0,9]` со start 3. Требуется `(0,2)`, но тест и код выбирают `(3,2)` из-за меньшего начального значения 0.

## [P1] Singleton возвращается с нулевой длиной

Для `[42]`, limit 0 единственный элемент является допустимым подмассивом, поэтому результат `(0,1)`. Строка 26 возвращает `(0,0)`.

**Уточнение после review:** это следовало из общего определения, но не было явно прописано отдельным граничным случаем. Не учитывается как ошибка пользователя до уточнения контракта.

## [P1] Переполнение меняет математическое условие

Для `[int.MinValue, int.MaxValue]`, limit 1 математическая разность равна 4 294 967 295, поэтому результат `(0,1)`. Выражение `max - min` вычисляется в `int`, переполняется до `-1`, а `Math.Abs` превращает его в 1; текущий код ошибочно принимает пару.

## [P1] Порядок валидации зависит от содержимого

- `values.Any()` вызывается до явной проверки `values == null`, поэтому ветка null на строках 14–18 недостижима.
- Для пустого списка и отрицательного `maxDifference` метод возвращает `(0,0)` до проверки аргумента, хотя контракт требует `ArgumentOutOfRangeException`.

**Уточнение после review:** исходное ТЗ не задавало приоритет между правилами «пустой список → `(0,0)`» и «отрицательный limit → исключение». Это была неоднозначность задания, а не подтверждённая ошибка пользователя. Контракт теперь явно требует проверять аргументы до обработки пустого списка.

## Сложность

Перебираются длины (`O(n)`) и все окна каждой длины (`O(n)`), а `Max()` и `Min()` повторно обходят каждый кандидат (`O(n)`). Суммарно это `Θ(n³)` времени, плюс большое число LINQ-итераторов. Требование задания — `O(n log n)` или лучше. Память словаря — `O(n)`.

Оптимизацию следует делать после фиксации корректного контракта тестами.
