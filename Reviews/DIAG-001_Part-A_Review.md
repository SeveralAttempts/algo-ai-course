# Review — DIAG-001, часть A

Дата: 2026-07-21. Это профиль навыков, не единая оценка.

## Поправки к условию

- В A2 исходный вопрос о двух функциях одного класса был дефектным: такой пары в списке нет. Эта часть не оценивается. После добавления `n` пара была бы `n` и `n + 1`, обе `Θ(n)`.
- В A5 действительно отсутствовал `x`. Наблюдение пользователя верно; условие исправлено на `x = 3`. Ошибка оценивается только в последующем рассуждении при самостоятельно выбранном `x = 1`.

## Разбор

| Пункт | Наблюдение | Корректировка |
|---|---|---|
| A1 | Предусловие смешано с граничным случаем | Предусловие: массив не `null` и не пуст. Постусловие: возвращён допустимый индекс первого минимума. Один элемент — граничный случай. |
| A2 | Интуитивный смысл роста известен, порядок функций неверен | `1 < log n < n + 1 < n log n < n² < 2ⁿ`. Общий множитель не делает классы одинаковыми. |
| A3 | Применено неверное правило «два цикла → n²» | Работа равна `1 + 2 + 4 + ... <= 2n`, поэтому `Θ(n)`. Важны суммарные границы, а не форма вложенности. |
| A4 | Повторное перечисление не распознано | `Any()` и `Last()` могут перечислить ленивый источник дважды. Это может повторить вычисления/побочные эффекты; для общего `IEnumerable` `Last()` стоит `O(n)`, хотя коллекции допускают оптимизацию. `Console.WriteLine` не является подвохом. |
| A5 | Дефект условия найден; трассировка при `x=1` неверна | Получается `(left,right,mid): (0,5,2) -> (0,2,1) -> (0,1,0) -> (0,0)`; цикл завершается и возвращает `0`. Метод возвращает первый индекс с `a[i] >= x`, либо `a.Length`. |
| A6 | Построен содержательный контрпример локальной жадности | Чтобы исключить возврат назад, рёбра лучше явно считать ориентированными. Идея контрпримера корректна. |
| A7 | Рекурсивный код распознан неверно | Это наивное вычисление чисел Фибоначчи для `n >= 0`: время экспоненциальное, стек `O(n)`. Проблемы: отрицательный контракт, повтор вычислений, overflow и stack overflow. |
| A8 | Словарь выбран разумно, но хранится больше данных, чем требует контракт | Если timestamps не нужны, достаточно `Dictionary<UserId,int>`. Update/query — ожидаемо `O(1)`; редкий top-10: просмотр с min-heap размера 10 — `O(u log 10) = O(u)` или сортировка `O(u log u)`. |
| A9 | Формальная техника пока отсутствует | Перед итерацией с индексом `i`, `max` равен максимуму префикса `a[0..i)`. Из этого следуют инициализация, сохранение и итог для всего массива. |
| A10 | Overflow найден верно; сомнение про будущий элемент разрешимо | Пара не теряется: когда будущий элемент станет текущим, ранний уже будет в `seen`. Проверяются разные позиции, включая дубликаты. В unchecked-контексте переполнение вычитания способно дать ложный ответ; безопасно считать дополнение в `long`. |

## Подтверждённые сильные стороны

- Замечена неполнота условия A5, а не молча подставлено скрытое предположение.
- Построен контрпример неправильной жадной стратегии.
- В A8 учтена разная частота операций и предложен приемлемый базовый контейнер.
- В A10 обнаружен C#-риск переполнения `int`.

## Подтверждённые пробелы

Формализация контракта и инварианта; вывод сложности зависимых циклов; ручная трассировка границ; чтение рекурсивного кода; повторное перечисление `IEnumerable<T>`. Это определяет стартовую глубину, но практическая реализация ещё не оценена.
