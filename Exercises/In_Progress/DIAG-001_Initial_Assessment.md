## Часть B — практическая (60–90 минут, после разбора A)

### B1. Реализация и тесты

Реализуйте на C# метод:

```csharp
public static (int Start, int Length) LongestStableSegment(
    IReadOnlyList<int> values,
    int maxDifference)
```

Он возвращает самый длинный **непрерывный подмассив**, то есть элементы с последовательными индексами `values[Start]`, `values[Start + 1]`, …, `values[Start + Length - 1]` без пропусков. Элементы не обязаны возрастать, убывать или быть одинаковыми. Единственное условие: разность между максимальным и минимальным значениями внутри выбранного подмассива не превосходит `maxDifference`, то есть `max - min <= maxDifference`.

Здесь `min` и `max` — не два случайно выбранных элемента: это наименьшее и наибольшее значения **среди всех элементов кандидата**. Эквивалентная формулировка: разность между любыми двумя значениями выбранного подмассива не должна превышать `maxDifference`; достаточно проверить минимум и максимум, потому что именно они образуют наибольшую разность.

Например, для `[8, 2, 4, 7]` и `maxDifference = 4`:

- `[8, 2]` не подходит: `max = 8`, `min = 2`, разность `6`;
- `[2, 4]` подходит: разность `2`;
- `[2, 4, 7]` не подходит: разность `7 - 2 = 5`;
- `[4, 7]` подходит: разность `3`.

Максимальная длина равна 2; из двух вариантов выбирается более ранний `[2, 4]`, поэтому ответ `(1, 2)`.

При равной длине выбрать сегмент с меньшим `Start`, где `Start` — **нулевой индекс начала**, а не значение первого элемента. Например, между `(0, 2)` для `[5, 14]` и `(3, 2)` для `[0, 9]` выбирается `(0, 2)`, несмотря на то что `0 < 5`.

Контракт граничных случаев и порядок проверок:

1. `values == null` → `ArgumentNullException` с именем параметра `values`;
2. `maxDifference < 0` → `ArgumentOutOfRangeException` с именем параметра `maxDifference`, независимо от длины списка;
3. пустой список при неотрицательном `maxDifference` → `(0, 0)`;
4. список из одного элемента при неотрицательном `maxDifference` → `(0, 1)`, поскольку `min == max` и разность равна нулю.

При пересечении условий применяется первый подходящий пункт в этом порядке. Пункты про singleton и приоритет проверки отрицательного `maxDifference` добавлены после обнаружения неоднозначности исходной формулировки и не учитываются как ошибки первой/второй попытки.

Примеры:

- `[8, 2, 4, 7]`, `4` → `(1, 2)`;
- `[10, 1, 2, 4, 7, 2]`, `5` → `(2, 4)`, подмассив `[2, 4, 7, 2]`;
- `[4, 4, 4]`, `0` → `(0, 3)`.

Ограничения: до 200 000 элементов; значения — любые `int`; входной список **не отсортирован** и может иметь произвольный порядок. Исходный порядок необходимо сохранить, потому что он определяет непрерывность сегмента. Сортировать весь ввод или переставлять элементы нельзя. Ожидаемое время `O(n log n)` или лучше, дополнительная память `O(n)` или меньше. Сначала напишите 6+ тестов, включая overflow-sensitive случай.

Размещение:

- реализация — `src/Algorithms/Diagnostics/StableSegment.cs`, класс `Algorithms.Diagnostics.StableSegment`;
- тесты — `tests/Algorithms.Tests/Diagnostics/StableSegmentTests.cs`, класс `Algorithms.Tests.Diagnostics.StableSegmentTests`.

Метод `LongestStableSegment` объявите `public static` в классе `StableSegment`. Обе папки `Diagnostics` при необходимости создайте самостоятельно. Рабочая директория для команд — корень репозитория, где находится `AlgorithmsLearning.sln`.
